# Sidelook architecture constraints

- Sidelook may use only models from the catalog in `public/models.js` (OpenAI models through Codex, Anthropic models through Claude Code), through existing **OpenAI or Anthropic monthly subscriptions**, plus local models that LM Studio or Ollama serve on the user's own computer (see the 2026-09-06 note below).
- **Never integrate or call a metered model API directly.** No API keys, API-key helpers, Google models, or API fallback, including during tests. The maintainer explicitly authorized Claude subscription usage credits for Fable on 2026-09-05; this exception is limited to the official Claude Code subscription path. The maintainer extended that authorization to every Anthropic catalog model on 2026-09-05, when the model catalog expanded.
- Users may select an OpenAI model through official Codex authenticated with ChatGPT, or an Anthropic model through official Claude Code authenticated with Claude. Missing subscription authentication, unavailable model access, and usage limits must fail closed. Never switch models automatically.
- Core architecture or model changes require an explicit discussion with the maintainer before implementation. Credential availability is not an architectural justification. The maintainer requested the model-catalog expansion on 2026-09-05, satisfying that discussion requirement for this change.
- Preserve camera sharing alongside screen capture and show which frame was used. Live build was explicitly approved by the maintainer: separately consented, bounded screen snapshots only. Never silently upload a live stream or capture audio.

These constraints apply to development, verification, and published code.

- The maintainer explicitly approved Computer mode on 2026-09-05: a local Windows accessibility broker, opt-in sessions, per-action review, and emergency stop. Models still return structured data through the existing isolated subscription transports; do not enable arbitrary CLI tools. Keep fixed launch targets, fresh target validation, and fail-closed action permissions.
- The maintainer approved Screen on on 2026-09-05: a leased, visible follow of the clicked window with an optional local screenshot in the box. It sends nothing on its own; automatic sends were considered and left out.
- The maintainer approved local open-weight models on 2026-09-06, as the one non-subscription path: LM Studio and Ollama on the user's own computer, reached only through the official Codex CLI's open-source provider (`codex exec --oss --local-provider lmstudio|ollama`, `lib/local.mjs`). The server enumerates what the runtime holds and the page chooses from that list; a runtime that is down or a model that is gone fails closed. Still no API keys, no metered endpoints, no remote hosts, no arbitrary CLI arguments from the page, and no automatic switching between a local model and a subscription model.
- The maintainer requested Agent mode on 2026-09-10 for the multi-app agent hackathon: a bounded tool-using agent over Slack, Stripe, HubSpot and Gmail with every consequential write governed by DashClaw through its official Node SDK (`dashclaw`, the one runtime dependency, used only by Agent mode). The model keeps the existing isolated CLI transports and structured output; it gets a finite typed tool registry and never a shell, a browser or arbitrary HTTP. Application credentials are read only by `lib/agent/config.mjs` from `.env` in the server process and never reach a model runtime, the page or DashClaw evidence. Stripe is test mode by default and a live key is refused for writes without `STRIPE_ALLOW_LIVE=1`. Computer mode is unchanged. Contract: `docs/AGENT_MODE_IMPLEMENTATION.md`.
