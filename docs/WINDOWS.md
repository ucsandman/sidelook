# Windows download

Sidelook 0.17.0 is a self-contained Windows 10/11 x64 executable. Download it from the site and open it. It extracts once, opens the native companion, and adds Desktop and Start menu shortcuts. No terminal, no Node, no npm, no admin.

Press **Ctrl+Shift+Space** to summon the companion. It starts as a compact conversation panel; Settings opens the studio beside it or Computer mode inside it. It needs the Microsoft Edge WebView2 Runtime. Sidelook checks for it and points you at the install if it's missing.

Choose a model and an effort level in Settings. Sign-in is a button in Settings that runs the chosen official CLI's browser flow. Codex is bundled. For Anthropic models, Settings downloads and verifies official Claude Code 2.1.261 with one install button. No Anthropic binaries ship inside the exe. Your subscription's access and limits still apply, and Anthropic models can spend paid usage credits. There's no API key and no paid API fallback. Closing the companion leaves Sidelook in the tray. **Quit Sidelook** stops its owned process tree. Opening the shortcut again reuses the running session. If another app holds port 4317, Sidelook shows an error rather than trusting that app.

The launcher is unsigned, so Windows may show an unknown-publisher warning. The release ships SHA256SUMS.txt, and the build verifies the bundled Node and Codex publishers. A checksum catches a changed download. It's not a publisher signature.

## Updates and removal

Agent mode's application credentials (see docs/HACKATHON_SETUP.md) go in `%LOCALAPPDATA%Sidelook.env` for the installed app; a source checkout reads the repo's `.env` instead. Neither file is copied into a build.

Quit Sidelook from the tray, then open the new download. Each build extracts into its own directory under `%LOCALAPPDATA%\Sidelook\versions` and the shortcuts move to it. Saved work stays in Sidelook's persistent desktop profile. A browser profile from a source install, or an older browser-based install, is separate, so its revisions don't come across on their own. Export the HTML you want to keep, then use **Settings, then Import a saved HTML prototype** in the companion. Imports cap at 120,000 bytes and add a version only when the 12-slot history has room. Older extracted versions stay on disk, and opening an old download after quitting the current one restores its shortcut.

To remove Sidelook, quit it, then delete its shortcuts and its Sidelook folder under local application data in File Explorer. Desktop-profile projects and the official Codex login are separate things: **New project** clears the current saved project, and removing Sidelook neither signs you out nor touches another Codex install's credentials.

## Developer packaging

After building, with Sidelook quit, run `powershell -NoProfile -File scripts/verify-desktop-host.ps1` and `node scripts/verify-desktop-content.mjs`. The first checks the real panel, dock, shortcut registration and reopening. The second uses an isolated desktop profile and a temporary localhost debugging connection to verify the embedded interface, prototype interaction, download, synthetic camera and a dedicated capture fixture. Neither makes a model request. Normal launches never enable debugging.

Run `npm run build:windows` on Windows x64 with Node 24, npm and the installed .NET Framework C# compiler. It downloads Node 24.15.0 and official Codex 0.153.4 with pinned integrity values, checks upstream publisher signatures, embeds `desktop/sidelook.ico` as the exe icon, and packs a fixed allowlist of app files into a WinForms launcher. A fresh staging directory keeps old files out of a new package. Upstream license notices are included. No local profile, credential file or user revision gets packaged. If you change the mark, run `powershell -NoProfile -File scripts/build-icon.ps1` first to regenerate the icon.

Run `npm run verify:windows` to exercise extraction with a system-only PATH, bundled CLI discovery, an explicitly isolated signed-out CLI status probe, desktop session protection, and rendered setup, preview and reload behavior. Windows account-level auth can survive HOME overrides. The packaged server check doesn't claim a new OS account or change the existing login. No model call is made. With port 4317 free, `powershell -NoProfile -File scripts/verify-windows-lifecycle.ps1` checks occupied-port refusal, repeated launches, Quit and forced-exit cleanup. These checks render the embedded app. Release assets are `Sidelook-0.17.0-Windows-x64.exe` and `SHA256SUMS.txt` under `.artifacts/windows-0.17.0`. Publish both only after verifying the final build.

The transient `SIDELOOK_DESKTOP_KEY` is generated by the launcher and passed only to its Node child. It's not a user setting and must never live in an environment file. Node consumes and removes it right away. The browser strips its fragment from the visible URL, keeps the key in session storage scoped to the exact origin including the port, and sends it only in an API header. No auth cookie. Never log the launch URL or the process environment.

## Computer control

Version 0.8 bundles the Windows accessibility controller source and its PowerShell launcher, so nothing extra to install. The companion can suggest Computer mode, but only its explicit workflow button opens it, and the consent and per-action review gates still apply. Ctrl+Shift+F12 has to be free before a session can arm. Stop any other Sidelook session using that shortcut first, Computer mode or Screen on. Protected windows and apps without supported accessibility patterns refuse actions. See [Computer mode](COMPUTER.md).
